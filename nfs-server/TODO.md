  **Resolved:** the app mounts the `nfsd` filesystem on startup (which also autoloads the `nfsd` kernel module on hosts that ship it). It turns out Home Assistant OS already includes the module (`CONFIG_NFSD=m`) for Rockchip-based boards (ODROID-M1/M1S, Home Assistant Green) – verified for HAOS 18.3. On all other boards (e.g. Raspberry Pi, x86_64), the HAOS kernels lack `CONFIG_NFSD` entirely, so the app cannot work there. Follow-up: suggest enabling `CONFIG_NFSD=m` for all HAOS kernels upstream in the [Home Assistant OS repo](https://github.com/home-assistant/operating-system) (the NFS *client* `CONFIG_NFS_FS` is already built into all of them).

- On HAOS 18.3 (odroid-m1, kernel 6.18.52), the app's original `echo "-2 -3" > /proc/fs/nfsd/versions` failed with `write error: Invalid argument` and left NFSv3 enabled, although the 6.18.52 kernel sources (`fs/nfsd/nfsctl.c`) suggest that requests to disable non-available versions are silently ignored, and `rpc.nfsd`'s own version write (which also starts with a `-2` token) succeeded right after. We now only reference versions the kernel actually offers and verify the outcome afterwards. Worth a host-side experiment (`echo "-2 -3"` vs. `echo "-3"` against a fresh nfsd mount) and, if the behavior is confirmed, an upstream report.

  **Resolved (root cause found via a reproduction lab in a privileged container on the dev machine's host kernel):** it was never about NFS version semantics. The app image's bash (`5.3.9` in the HA app base image) implements `echo`/`printf` output as a `writev(2)` call with the text and the trailing newline as separate iovecs, while the kernel's nfsd control files (`fs/nfsd/nfsctl.c`, `transaction_ops`) only implement the old-style single-buffer `.write` and no `.write_iter` – on modern kernels, `writev(2)` against such files fails with `EINVAL`. Hence *any* `echo`/`printf` redirection into `/proc/fs/nfsd/*` fails in the app, while single-write callers succeed (verified: busybox `echo`, `cat` via tmpfs staging, and `rpc.nfsd`'s own version write all work; strace showed `writev(1, [{"-3", 2}, {"\n", 1}], 2) = -1 EINVAL`). The pre-start version write was redundant anyway (rpc.nfsd configures the versions itself via `--no-nfs-version 3`, verified end state `-3 +4 +4.1 +4.2`), so it was removed. If a direct write to `/proc/fs/nfsd/*` is ever needed again: stage the string in a regular file (e.g. on tmpfs) and `cat` it – single `write(2)`.
